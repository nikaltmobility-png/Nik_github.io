1. Master Conversation Flow Top level

This is the spine of every call. It covers the opening, every possible first response from the customer, and where each response routes to. The dotted arrows show that the interrupt handler (Diagram 7) can fire from literally any state — a customer can ask a price question in the middle of the opening, and the agent answers it, then returns exactly here.

flowchart TD
    A["Inbound lead assigned to AI agent"] --> B["Opening:
'Aapne 3-wheeler ke liye enquiry ki thi.
Vehicle lene ka plan kar rahe hain?'"]
    B --> C{"Customer's first response"}

    C -->|"Clear yes / positive intent"| D["Ask vehicle type:
Cargo/Loader vs Passenger vs Unsure"]

    C -->|"'Price batao'"| E["Ask which product first,
then quote price"]
    E --> I["Ask: 'Aap vehicle kis location
mein lena chahenge?'"]

    C -->|"'Bas enquiry ki thi'"| F{"Info only, future plan,
or actually positive?"}
    F -->|"Information only"| Z3["INFORMATION FLOW:
answer questions, offer WhatsApp/brochure,
soft close, no pressure"]
    F -->|"Future plan"| J["Go to Follow-up Flow
(Diagram 5)"]
    F -->|"Actually positive"| D

    C -->|"'Maine koi enquiry nahi ki'
(wrong lead)"| G["Ask: 'Kya abhi 3-wheeler
ki requirement hai?'"]
    G -->|Yes| D
    G -->|No| Z1["🔴 Disposition: WRONG NUMBER
Status: UQ — Exit pipeline
Flag number for data cleanup"]

    C -->|"'Abhi busy hoon'"| H["Ask convenient callback time"]
    H --> Z2["🟡 Disposition: CALL BACK
Status: Q — Due: time lead requested
(guardrail: within shift hours)"]

    D --> K{"Which vehicle type?"}
    K -->|"Cargo / Loader"| L["Go to Cargo/Loader Flow
(Diagram 2)"]
    K -->|"Passenger"| M["Go to Passenger Flow
(Diagram 3)"]
    K -->|"Unsure"| N["Ask: 'Goods/delivery ke liye
ya passenger use ke liye?'"]
    N -->|Goods| L
    N -->|Passenger| M
    N -->|"Business/other, unclear"| N2["Ask: 'Vehicle ka use
kis type ke kaam mein hoga?'"] --> N

    L --> I
    M --> I

    I --> O["Go to Location & Serviceability Flow
(Diagram 4)"]
    O --> P{"Intent positive AND
serviceable location confirmed?"}
    P -->|Yes| Q["🟢 SQL — CONNECTED FOLLOW UP
Status: Q → Handoff to human sales
Pass: name · intent · timeline · location · budget"]
    P -->|"No — future / non-serviceable / objection"| R["Route to Disposition Flow (5)
or Objection Flow (6)
as applicable"]

    B -.->|"Question mid-flow"| S(("Interrupt Handler
(Diagram 7)"))
    D -.-> S
    I -.-> S
    L -.-> S
    M -.-> S
    O -.-> S
    S -.->|"Answer, then return"| B
Rule: the agent never runs this as a rigid script — every arrow is a possible branch based on what the customer actually says, and the interrupt handler can fire between any two boxes.

4. Location & Serviceability Flow Core / v2 update

Serviceable = customer can physically reach a dealership. Not where he'll drive the vehicle later. The key v2 addition: before disqualifying anyone, the agent must always ask for an alternate location — a non-serviceable close is only allowed after that check fails.

flowchart TD
    A["Ask: 'Aap kis area/location mein hain?
Kis showroom visit kar sakte hain?'"] --> B["Capture CUSTOMER_LOCATION"]
    B --> C{"Match locality against
dealer-area mapping"}

    C -->|"Matches a dealership's
covered locality"| D["Confirm: '[Dealership] aapke
liye relevant rahega'"]
    D --> E{"Purchase intent already
confirmed positive?"}
    E -->|Yes| F["SQL = QUALIFIED
→ Master Flow closing (1)"]
    E -->|"No / unclear"| G["Re-confirm: 'Abhi lena hai
ya thoda baad mein?'"]
    G -->|Now| F
    G -->|Later| H["Go to Follow-up Flow
(Diagram 5)"]

    C -->|"Ambiguous area given
e.g. 'Delhi ke paas'"| I["Ask for exact locality/landmark.
Do not assume."]
    I --> C

    C -->|"No dealership covers
this locality"| J["MANDATORY STEP:
'Kya aapke paas koi aur location hai —
office, ghar ka doosra area, ya jahan
aap aksar aate-jaate hain?'"]
    J --> K{"Alternate location given?"}
    K -->|"Yes — and it matches coverage"| D
    K -->|"Yes — but still no match"| J
    K -->|"No alternate exists"| L["🔴 Disposition: OUT OF GEO LIMIT
Status: UQ — Exit pipeline
(never a hard close — sales team may
know of new coverage or partner options)"]
Rule: the agent must never jump straight from "no local dealership" to a non-serviceable close — the alternate-location question (box J) is mandatory every time.

5. Disposition Stage Flow — 6-Stage Schema v3 updated

Every call must end with exactly one of these six disposition tags (or SQL/Connected Follow Up for qualified leads). Leg 2 = customer side of the call. Q = re-queue active; UQ = exits pipeline.

flowchart TD
    START(["AI initiates outbound call"]) --> LEG2{"Leg 2 connects?
Customer side answers"}

    LEG2 -->|"❌ No Answer / Switched Off
Network Fail / Ring No Response"| D1["🟡 DISPOSITION 1: NC FOLLOW UP CALL
Status: Q — Re-queue for next dial
No conversation occurred"]

    LEG2 -->|"✅ Customer picks up"| REAL_CONV{"Real conversation?
Did lead share any intent
or info beyond hello?"}

    REAL_CONV -->|"❌ No — hello-hello then hung up
picked up but busy / can't talk
call dropped immediately"| D2B["🟡 DISPOSITION 2: CALL BACK (Default)
Status: Q
Due: Now + 4 hours
Guardrail: within shift hours only"]

    REAL_CONV -->|"✅ Yes — real exchange happened"| WRONG_CHECK{"Correct person?"}
    WRONG_CHECK -->|"Wrong person / Wrong number"| D6["🔴 DISPOSITION 6: WRONG NUMBER
Status: UQ — Exit pipeline
Flag number for data cleanup"]
    WRONG_CHECK -->|"Correct lead"| INTENT{"Determine Intent"}

    INTENT -->|"Negative intent
'Nahi chahiye' / 'Interest nahi'"| D3["🔴 DISPOSITION 3: NOT INTERESTED
Status: UQ — Exit pipeline
Set DND flag if requested"]

    INTENT -->|"Info only — no purchase plan
'Bas jaanna tha'"| D5_CHECK{"Any future plan
after gentle probe?"}
    D5_CHECK -->|"Still none"| D5["🔴 DISPOSITION 5: GENERAL ENQUIRY
Status: UQ — Exit pipeline
Info delivered, no pipeline value"]
    D5_CHECK -->|"Future intent found"| POS_INTENT

    INTENT -->|"Positive / Future intent"| POS_INTENT["Check serviceability"]
    POS_INTENT --> GEO{"Primary location
serviceable?"}
    GEO -->|"✅ Serviceable"| SQL_CHECK
    GEO -->|"❌ Not serviceable"| ALT["MANDATORY: Ask alternate location
'Kya aur koi location hai?'"]
    ALT --> ALT2{"Alternate
serviceable?"}
    ALT2 -->|"✅ Yes"| SQL_CHECK
    ALT2 -->|"❌ No after all checks"| D4["🔴 DISPOSITION 4: OUT OF GEO LIMIT
Status: UQ — Exit pipeline
Primary + alternate exhausted"]

    SQL_CHECK{"SQL criteria met?
Intent + location + budget
+ timeline all confirmed"}
    SQL_CHECK -->|"✅ Yes"| SQL["🟢 SQL — CONNECTED FOLLOW UP
Status: Q → Handoff to human sales
Pass: name · intent · location · budget · timeline"]

    SQL_CHECK -->|"❌ No — lead has shared intent & location
but asks for a callback"| D2A["🟡 DISPOSITION 2: CALL BACK (Requested)
Status: Q
Due: exact time lead specified
Guardrail: pull within shift hours"]

    SQL_CHECK -->|"❌ No — future timeline given
'6 mahine baad' etc."| FUTURE["AI negotiates cadence:
'Kya 1-2 mahine mein connect kar sakta hoon?'"]
    FUTURE --> FUTURE2{"Lead agrees
to shorter cadence?"}
    FUTURE2 -->|"✅ Agrees — 1 to 2 months"| D2C_SHORT["🟡 DISPOSITION 2: CALL BACK (Future — negotiated)
Status: Q
Due: Now + 30–60 days
Note: Lead agreed to early check-in"]
    FUTURE2 -->|"❌ Insists on full timeline"| D2C_LONG["🟡 DISPOSITION 2: CALL BACK (Future — lead's date)
Status: Q
Due: Lead's stated date
Note: Full cadence, no early pull-in"]
Rule: Every call leg must end with exactly one disposition tag — no exceptions. If a call drops mid-conversation with no clean disposition, default to Call Back (Default) — Now + 4 hrs — to avoid losing a lead from the pipeline. "Call Back" always means Leg 2 did connect. The sub-type only affects due-time logic.

6. Objection Handling Flow Sub-flow

Price, down payment, "let me think," competitor comparisons, CIBIL, documents, company purchase, and unknown questions — all resolved without arguing, then routed back to qualification.

flowchart TD
    A{"Objection / question type"}

    A -->|"'Bahut mehenga hai' (price)"| B{"What specifically?"}
    B -->|"Monthly payment"| C["Route to relevant Finance/EMI pitch
(Diagram 2 or 3)"]
    B -->|"Down payment"| D["Go to DP objection sub-branch"]
    B -->|"Overall price"| E["Explain lease structure / benefits
only as relevant — don't over-explain"]
    C --> F["Re-ask intent:
'Abhi lena hai ya baad mein?'"]
    D --> F
    E --> F
    F -->|Now| G["Return to SQL path
(Location Flow, Diagram 4)"]
    F -->|Later| H["Go to Follow-up Flow (5)"]

    A -->|"'Down payment bahut zyada'"| I["Ask: 'DP issue hai ya
monthly bhi concern hai?'"]
    I --> J["Understand financial comfort.
Never promise a lower DP unless
an approved plan exists."]
    J --> F

    A -->|"'Soch ke bataunga'"| K{"What needs thinking about?"}
    K -->|Price| B
    K -->|Finance| C
    K -->|Family| L["Go to Follow-up Flow (5) —
Family Approval"]
    K -->|"Money arrangement"| H

    A -->|"'Baaki brand sasti hai'"| M["Ask: comparing price,
running cost, range, or finance?"]
    M -->|Price| C
    M -->|"Running cost"| N["Need-analysis / economics pitch"]
    M -->|Range| O["Vehicle specs pitch
(Diagram 2/3)"]
    M -->|Finance| C
    N --> G
    O --> G

    A -->|"CIBIL question / low CIBIL"| P["No fixed minimum CIBIL. DP may
adjust for low profile. Finance team
confirms eligibility.
Never guarantee approval.
Never say 'reject / fail / not eligible.'"]
    P --> G

    A -->|"Documents / DL question"| Q["Normal DL works for both cargo & passenger.
Never say commercial DL is mandatory.
Learning-licence assistance if no DL.
Permit requirement varies by state —
capture state, route to permit KB / sales."]
    Q --> G

    A -->|"Company purchase question"| R["Confirm: possible, GST/company docs
accepted, not on wet lease.
Exact docs confirmed by finance/sales."]
    R --> G

    A -->|"Question not in approved KB"| S["Never invent an answer.
Say it will be confirmed and
shared with the sales team."]
    S --> G

7. Universal Mid-Call Interrupt Handler Applies everywhere

This subroutine can trigger from any box in any other diagram. It's what stops the call from sounding like a questionnaire — the agent always answers the real question first, then returns to exactly where it left off.

flowchart TD
    A["Customer asks a question or
raises a new topic mid-flow"] --> B{"Classify the question"}

    B -->|"Price / Finance / EMI"| C["Answer from approved pricing KB
for the relevant product"]
    B -->|"Specs / range / charging"| D["Answer from spec-sheet KB"]
    B -->|"Documents / DL / CIBIL / permit"| E["Answer per Documents & CIBIL flow
(Diagram 6), capture state if needed"]
    B -->|"Objection
(price/competitor/family/etc.)"| F["Route to Objection Handling
(Diagram 6)"]
    B -->|"Vehicle type change
e.g. cargo → passenger"| G["Update VEHICLE_TYPE, switch product
branch, discard old script entirely"]
    B -->|"Purchase mode change
e.g. buy vs rental"| H["Offer purchase vs
monthly/lease comparison"]
    B -->|"Wants human / WhatsApp"| I["Route to Follow-up &
Disposition Flow (5)"]
    B -->|"Anything not in approved KB"| J["Never invent. Acknowledge,
note for sales team."]

    C --> K["RETURN to the exact state the
conversation was in before the interruption"]
    D --> K
    E --> K
    F --> K
    G --> K
    H --> K
    I --> K
    J --> K
Rule: the agent should never repeat a question already answered, and never re-ask "are you interested?" once positive intent is visible — this handler exists precisely so the agent can be interrupted constantly without losing the thread.

8. Final SQL Decision — Compact Overview Summary

Everything above collapses into this single decision. If you only remember one diagram, remember this one.

flowchart TD
    A["Customer"] --> B{"Purchase intent positive?"}
    B -->|No| C{"Future intent with
a specific timeline?"}
    C -->|Yes| D["🟡 CALL BACK (Future)
Capture timeline, negotiate cadence"]
    C -->|"No — info only"| E["🔴 GENERAL ENQUIRY
Status: UQ"]
    C -->|"No — negative"| E2["🔴 NOT INTERESTED
Status: UQ"]

    B -->|Yes| F{"Location given?"}
    F -->|No| G["Ask location"] --> F
    F -->|Yes| H{"Serviceable —
can reach a dealership?"}
    H -->|Yes| I["🟢 SQL — CONNECTED FOLLOW UP
Status: Q → Handoff"]
    H -->|No| J["Ask alternate location
(MANDATORY)"]  
    J --> K{"Alternate serviceable?"}
    K -->|Yes| I
    K -->|No| L["🔴 OUT OF GEO LIMIT
Status: UQ
(not a hard close — log for sales team)"]
